# 스토리 2. “아이디어 1개로 기획서·공고문·안내문까지” 패키지 생산 워크숍
------------------------------------------------
##콘셉트
기획 아이디어 도출부터 정리까지 시간이 오래 걸리는 이유는 “기획서 하나”가 아니라 **연동 문서(공고문, 안내메일, 운영계획, 예산, 평가계획, 내부결재 문안)**가 줄줄이 필요하기 때문이다. 2시간 안에 문서 패키지를 한 번에 뽑아내는 경험을 제공한다.

##실습 프롬프트(기획 요소 추출)
아래 아이디어를 ‘대학 평생교육 프로그램 기획서’ 구조로 변환한다.
출력 항목:
1) 문제정의(왜 필요한가)
2) 대상(페르소나 2개)
3) 학습목표(측정 가능하게 3개)
4) 운영방식(시간표 포함)
5) 성과지표(KPI 5개)
6) 리스크와 대응(3개)
[아이디어]
(예시 A/B/C 중 선택한 아이디어 3~5줄)

##실습 프롬프트(기획서 본문)
방금 만든 기획 요소를 사용해 기획서 초안을 작성한다.
조건:
- 표 2개 포함(예산표, 회차별 운영표)
- 예산은 항목 단위로만 작성(세부 단가가 없으면 ‘추정’ 표시)
- 평가계획은 사전/사후 설문 + 만족도 + 성취도(간단 루브릭) 포함

##실습 프롬프트(공고문)
다음 기획서를 바탕으로 ‘모집 공고문’을 작성한다.
포함 요소:
- 과정 소개(3~4줄)
- 대상/정원/일정/장소(표)
- 신청 방법/문의처(형식적으로)
- 유의사항(환불, 출결, 저작권/촬영 관련 5줄)
톤: 공공기관 공고문 스타일
[기획서]
(초안 붙여넣기)

##실습 프롬프트(FAQ 10문 10답)
모집 공고에 자주 들어오는 질문을 10개 만들고,
각 답변은 2~3문장으로 명확하게 작성한다.
민원 유발 가능 표현을 피한다.

##실습 프롬프트(참가자 안내메일)
모집 확정자에게 보내는 안내메일을 작성한다.
포함:
- 환영 인사
- 준비물(노트북, 계정, 사전설치)
- 당일 일정(타임테이블)
- 자료 배포 방식
- 문의 및 유의사항
톤: 친절하지만 과장 없는 공문형 메일

##실습 프롬프트(내부결재 상신 문안)
센터장 결재용 상신 문안을 12줄 내외로 작성한다.
구성:
- 추진 배경
- 핵심 내용(대상/일정/예산 총액)
- 기대효과(정량 2개 + 정성 1개)
- 요청사항(결재/협조 2개)

##실습 프롬프트(개인 템플릿 저장용)
내 업무에 맞는 ‘재사용 프롬프트 5개’를 만들어 달라.
업무: (예: 과정 운영/정산/대외 공문/성과보고/홍보)
각 프롬프트는 복사해 바로 쓸 수 있게 입력칸(대괄호)을 포함한다.

- 문구는 공공기관 공고문 톤

금지: 과장, ‘100%’, ‘완벽’, ‘무조건’ 같은 단정 표현.
----------------------------------------------

4단계: 참가자 안내메일 + FAQ 10문 10답

구성: 환영/준비물/사전 설치/당일 일정/자료배포/문의/유의사항.

2) FAQ 10문 10답을 만든다.

-----------------------------------------------

5단계: 리스크 표현 검수(대외 문서 품질관리)
공고문과 FAQ에서 민원 유발 가능 표현, 책임소재가 불명확한 표현,
과장·단정 표현을 모두 표시하고 ‘안전한 행정 문장’으로 수정한다.

#실습 예시 3) 예산 집행/정산 서술 자동화 + 감사 대응형 증빙 체크리스트
<실습 목표>
* 정산/집행 내용을 “감사 대응 가능한 문장”으로 재구성한다.
* 누락 증빙을 자동으로 체크한다.
* 향후 동일 업무에 재사용 가능한 템플릿을 만든다.
<샘플 데이터>
###자료(더미)
* 사업: 2025년 2학기 단기과정 운영(3개 과정)
* 총예산: 3,800,000원 / 집행액: 3,430,000원(집행률 90.3%)
* 집행 항목
   * 강사료 2,500,000원(계약서/이체확인/원천징수)
   * 홍보비 470,000원(디자인 외주/게시 증빙)
   * 교재·자료비 270,000원(인쇄/구매내역)
   * 기타 190,000원(명찰/다과)
* 특이사항
   * 노트북 대여 2대 운영(대여대장 필요)
   * 일부 과정 출결 변동으로 환불 문의 발생(환불 규정 안내 기록 필요)
---------------------------------------------
1단계: 정산 서술문(결재용) 생성
###역할
너는 평생교육지원센터 정산 담당이다.

###목적
아래 자료로 ‘예산 집행 및 정산 서술’ 문단을 작성한다(결재/감사 대응 수준).

###제약
근거 없는 사실 생성 금지.
책임소재가 불명확하지 않게 작성.
민원 가능 항목은 규정 준수 표현으로 작성.

###출력형식
- 집행 개요 5줄
- 항목별 집행 내역(표)
- 특이사항 및 조치(불릿 5개)

###자료
(샘플 데이터를 붙여넣는다)

체크리스트를 기준으로 ‘현재 자료에서 누락된 증빙’과

각 항목은 (누락증빙/확보방법/담당/기한)으로 표로 출력한다.
----------------------------------------------

3단계: 재사용 템플릿(다음 학기 반복용) 생성
내가 다음 학기에도 그대로 복사해 쓸 수 있도록
‘예산 집행 보고 프롬프트 템플릿’과 ‘증빙 체크 템플릿’을 만들어라.
입력칸은 [대괄호]로 비워둔다.

#실습 예시 4) 회의록 → 결정사항/담당/기한 “구조화(JSON) 출력” + 공지문 자동 생성
<실습 목표>
* 회의록을 구조화해서 누락을 줄인다.
* 구조화 결과(JSON/표)로 공지문을 자동 생성한다.
<샘플 데이터>
###자료(회의 메모)
* 안건1: 3월 단기특강 모집 시작일 2/20, 홍보물 2/15까지 완료
* 안건2: 환불 규정 문구 통일 필요, 공고문에 출결 기준 명시
* 안건3: 노트북 실습 과정은 사전 설치 안내 링크 필수
* 결정: 모집 페이지는 구글폼 사용, 자료배포는 QR+메일 병행
* 담당: 홍보물(김A), 공고문 수정(박B), 설치 안내문(최C)
* 기한: 2/15 홍보물, 2/18 공고문, 2/19 설치 안내문
------------------------------------------------

1단계: 구조화(JSON)로 변환
아래 회의 메모를 JSON으로 구조화한다.
필수 키:
agenda_items[{title, decision, owner, due_date, notes}],
global_decisions[],
risks[],
followups[]
날짜 형식은 YYYY-MM-DD로 통일한다.
자료에 없는 정보는 null로 둔다.
(회의 메모를 붙여넣는다)
-----------------------------------------------

2단계: 구조화 결과로 공지문 생성
위 JSON을 바탕으로 내부 공지문을 작성한다.
형식: 제목/배경/결정사항/담당-기한 표/유의사항.
톤: 내부 공지 톤, 간결.
-----------------------------------------------

3단계: 누락·충돌 검증
JSON에서 담당/기한 누락, 날짜 충돌, 의사결정 불명확 항목을 탐지하고
추가 질문 5개를 생성한다.
